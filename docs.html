1About

The Elite Force Database is a community-built reference for Elite Force units in World Conqueror 4 (Easytech). Every unit in the game is documented by level, from stats and unlock costs to skills and unlock notes.

Units are organized into five types, matching the game's unit classes:

  • Infantry
  • Artillery
  • Navy
  • Armored
  • Air Force

The site is fully static — data lives as plain JSON files under data/, so anyone can contribute a unit by adding or editing a file and opening a pull request.

2Using the Database

  1. Search — type into the search field on the main page, or pick a unit from the dropdown. Search matches unit names while you type; use ↑/↓ and Enter to select.
  2. Filter by type — the buttons above the panel (Infantry / Artillery / Navy / Armored / Air Force) restrict the dropdown to one unit class.
  3. Pick a level — slide or type a level between 1 and 12. The dossier updates instantly.

Reading a unit dossier

Element What it tells you
Stat bars Attack, Defense, Movement and HP at the selected level, compared against the highest value any unit of that type reaches.
Skill chips Skills owned at the current level. Color = tier: Bronze / Silver / Gold / Platinum. Hover a chip to read its description.
Locked skills Skills the unit will unlock at higher levels, each marked with its unlock level.
Upgrade / Unlock Cost The cost to unlock or upgrade this level, in Frags, Money, Industry and/or Honor Badges.
Note Extra context for the level, e.g. which skills upgrade or unlock here.

3Unit Data Format

Each unit is a single JSON file at data/<type>/<Unit Name>.json. The id used by the app is the filename without the .json extension. 

{
  "name": "Delta Force",
  "unit_type": "Infantry",
  "levels": [
    {
      "level": 1,
      "stats": { "attack": 72, "defense": 20, "movement": 15, "hp": 385, "range": 1 },
      "cost": { "pieces": 30, "money": 0 },
      "skills": [
        { "title": "Grenade", "tier": "gold",
          "description": "Damage to armored units +50%" }
      ],
      "note": "null"
    }
  ]
}

Fields

Field Type Description
name string Display name of the unit.
unit_type string Human-readable type label (e.g. "Infantry"). The folder determines the type, this is informational.
levels array Up to 12 level entries, in order (level 1 to level 12).

Level entry

Field Type Description
level number The level number (1–12).
stats object attack, defense, movement, hp, range. Use 0 for "not applicable" (e.g. units with no ranged attack have range: 1; placeholder levels with no new stats use all zeroes).
cost object | omitted pieces (Frags), money, industry, honorInfantryBadges (Honor Badges). Omit keys that cost nothing.
skills array | omitted Each skill: title (string), tier (bronze | silver | gold | platinum), description (string).
note string | omitted Unlock/upgrade notes. Use the literal string "null" (or omit) when there is no note.
Conventions — levels with no changes at all keep the previous stats; use all-zero stats only when the game shows nothing yet. Skill here means an ability owned at that level — a skill only listed once a level where it appears or upgrades.

4Adding or Editing Units

1. Manual JSON + manifest

# 1. create (or edit) data/<type>/<Unit Name>.json
# 2. regenerate the unit index:
node generate-manifest.js

The manifest scan reads every *.json under data/, sorts units by name, and rewrites data/units.json. Running it is required after adding, renaming or deleting a unit file.

2. Commit and let CI do it

On every push to main, the update-units GitHub Action re-runs generate-manifest.js and commits data/units.json if it changed. So a simple pull request adding a JSON file is fully sufficient — no tooling needed.

5Maintenance

What's New panel

The What's New? panel is fed by whats-new.txt in the repo root. Put the date on its own line, then the entry lines below it: 

August 10, 2026

Updated notes for infantry units: Brandenburgers, Combat Medic, Engineering Unit

Status light

State Meaning
STANDBY / IDLE Page loaded, idle.
LOADING Fetching a unit file or stats.
RECORD FOUND Unit + level data displayed.
NO UNITS / NO RECORD / FETCH FAILED A data or fetch problem — see troubleshooting.

Caching

Data fetches are cache-busted with a query string (?v=), so new unit files appear without a hard refresh in most setups.

6Troubleshooting

Problem Cause & fix
"No units available yet." data/units.json is missing or empty. Run node generate-manifest.js (or push to main so CI regenerates it).
"No record for … at level N." The unit file has no entry for that level. Add a levels entry (or all-zero placeholder).
"Could not load units…" on the live site Unit JSONs were added but never committed, or data/units.json is stale. Commit both the new file and the regenerated manifest.
Unit missing from search / dropdown Filename or name mismatch — the manifest id comes from the filename, and search matches the name field. Regenerate the manifest and check the type folder matches the correct class.
